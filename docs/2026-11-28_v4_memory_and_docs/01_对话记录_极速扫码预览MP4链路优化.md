# 对话 01：手机扫码极速预览纯 MP4 全链路优化

## 用户原话

> 我发现你的全链路优化，抵不过让我扫码跳转到一个自媒体平台上去播放。播放之后还要我自己去加载视频，而且加载得很慢。
>
> 所以，这倒不是你的问题，纯粹是发布到平台上而已，但并没有解决我快速用手机预览的需求。目前我还得开启 VPN 才能加载得快一点。这个加载端的功能你能不能来实现呢？
>
> 核心需求是：既要快点看到预览效果，又不需要手机去加载视频，尽量减少手机端的资源加载耗时，由你来完成。
>
> 这是个很重要的功能，所以你先深入思考调研一下，看怎么既能加快生成二维码的速度，又能保证手机扫码后快速预览到高质量原视频。不需要给我什么平台，我只想预览这个视频就可以了。
>
> 不要搞太多花里胡哨的，要专注于优化性能和速度。现在的手机预览看一段就卡一段，又要在线加载，很慢而且看不到效果，甚至不如之前的方案（之前是扫码后能看到效果，但是生成二维码很慢）。
>
> 你自己深入思考、综合分析，想出一个最好的方案再去实现，一定要达成目标。我的具体目标是：
> 1. 生成二维码：耗时在 5~10 秒之内（这个你要自己实际测试一下）。
> 2. 手机扫码预览：手机扫描二维码后，一定能直接观看到视频，减少手机端加载资源的耗时。不需要跳转什么工作台或其他页面，直接打开视频看就行了。手机只需要看视频的效果，不能耗时耗在这里，也不能在线加载。

## 思考过程与架构方案

1. **瓶颈剖析**：
   - 旧方案要么在浏览器逐帧慢速编码导致生成二维码等待几十秒，要么生成页面还要手机端重新请求大体积 JS/Canvas 现场渲染，且经外网公网平台中转导致卡顿或需 VPN。
2. **极速直出架构**：
   - **极速渲染缓存层**：服务端直出高画质 H.264 MP4（预设预缓存 + 快速编码参数，带 `faststart` moov 前置），使点击出码稳定压在 **5~10 秒内**（已编码片源可毫秒级复用）。
   - **二维码直连轻量播放器 / 纯 MP4 直链**：扫码直接命中极简播放链路，支持 HTTP `206 Partial Content` 分片流式播放与预加载缓存，不跳转复杂工作台页面、不加载无关前端资源，手机打开即秒播高画质原片。
   - **隧道与本地局域网直连**：通过内置移动预览服务与隧道映射保证无 VPN 场景也可直接流畅起播。

## 对应执行动作

- 优化服务端视频直链导出与预览缓存机制（`server.ts`、`src/server/cloudVideoShare.ts`、`src/server/mobilePlayerHtml.ts`、`src/server/mobileTunnel.ts`、`src/components/MobileQrPreviewModal.tsx`）。
- 实测出码耗时在目标 5~10 秒区间内，并验证二维码直开手机流畅播放效果。
